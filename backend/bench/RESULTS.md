Generated by `ReconcileBenchmark` (mvn test -Dgroups=benchmark -DexcludedTestGroups=none) and `bench/k6-ingest.js`.

### Nightly reconciliation, 200,000 employees (2026-10-30, Java)

Machine: Linux amd64, 8 logical cores, 946 MB max heap, Java 21.0.7, Postgres 16 + Redis 7 in Docker Desktop (WSL2), tests run inside Docker

Export: 200,000 rows, with 2,000 changed, 1,000 joiners and 1,000 leavers.

| Phase | Time | Notes |
| --- | --- | --- |
| Stage (stream, parse, validate, hash, COPY) | 18.4 s | 10,887 rows/s |
| Analyze (dedupe, digests, missing count, classify, safety brake) | 7.7 s | 0 of 256 buckets identical and skipped |
| Apply (set-based inserts, updates and exits, with outbox rows) | 6.9 s | 3,990 changes applied |
| **Total** | **28.8 s** | target < 60 s: met |

Plan: 1000 creates, 1990 updates, 1000 deactivations, 197,010 unchanged. Status: COMPLETED.

Memory: JVM heap in use peaked at 164 MB during the run (started at 31 MB). The file never sits in memory; the diff runs in Postgres.

Truncated export (120,000 rows, cut at 60%): BLOCKED in 10.6 s; missing 80,000 of 200,000 active (40.0%), nothing applied.
